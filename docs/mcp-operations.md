# MCP: фоновые операции и компактная диагностика

MCP выполняет операции инструментов в одном worker thread. Полная пересборка
SQLite-индекса при устаревании больше не выполняется в потоке stdio MCP.
Последовательная очередь worker сохраняет порядок записей и не запускает
несколько одновременных пересборок внутри одного MCP-сервера.

`get_project_brief`, операции document tree/outline/section и получение статуса
операции выполняются в основном потоке и доступны, пока worker занят.
Остальные запросы становятся в общую очередь: одновременная подача не означает
одновременное исполнение. CLI и библиотечные функции остаются синхронными.

## Долгая операция

Если инструмент не завершился за пять секунд, он возвращает `status: RUNNING`,
`operationId` и `fullResultUri`. Это не готовый context pack и не устаревшая выдача.
Вызовите `get_operation_result({operationId})`, чтобы получить состояние.
У завершённой операции `status: COMPLETED`, а данные находятся в `result`.
Ошибка worker/операции даёт `FAILED`, неизвестный/удалённый ID — `NOT_FOUND`.

**Не повторяйте исходный вызов после RUNNING**, особенно изменяющий данные:
он уже принят и может выполняться. Отмена ожидания клиентом не отменяет работу.
Worker не повторяет операции автоматически после сбоев; проверьте фактическое
состояние проекта перед самостоятельным повтором записи.

Одновременно принимается до восьми незавершённых операций. Переполненная очередь
отклоняет новый вызов до выполнения. Завершённые результаты сохраняются только
в памяти текущего MCP-процесса: старые снимки вытесняются после новых операций,
а перезапуск удаляет их. Это не долговечное хранилище evidence.

## Полная диагностика

`context_doctor({fixDryRun:false})` по умолчанию возвращает сводку: статус,
счётчики и не более трёх примеров по каждому диагностическому пункту. Размер
каждого примера ограничен. `detailCount` показывает полный размер списка.
Для fixDryRun сводка показывает до пяти предложений без полного содержимого.
Короткий текст MCP указывает на structuredContent и не копирует весь JSON.

Доступ к **тому же полному снимку**:

- прочитать `fullResultUri` через MCP resource;
- вызвать `get_operation_result({operationId, detail:"full"})`;
- запросить `context_doctor({detail:"full"})` для новой полной проверки.

Полная выдача не сокращается. Вызов `detail:"full"` может быть большим по явному
запросу. MCP resource doctor также выполняется через worker, не блокируя stdio.

CLI `lint` и `doctor` выдают сводку по умолчанию. Для всех данных используйте
`project-context lint --full --json` и `project-context doctor --full --json`.
CLI повторно выполняет диагностику; это новый снимок, а не сохранённый MCP-результат.
Код возврата определяется полной проверкой, даже когда подробности сокращены.

## Ограничения

Изоляция освобождает поток MCP, но не ускоряет саму пересборку и не даёт прогресс
в процентах. Общая очередь означает, что другие тяжёлые инструменты будут ждать.
Несколько независимых MCP-процессов не делят worker или очередь; действуют
существующие SQLite-транзакции и блокировки. Защита путей и свежесть индекса не
отключаются. При больших ответах остаются расходы на передачу/сериализацию данных.
