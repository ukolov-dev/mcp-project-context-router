# Связи символов: explain, affected, path

Router хранит статические связи TS/JS в существующем SQLite-индексе. Используется
TypeScript 5.9.3 compiler API; внешняя графовая база и вызовы LLM
не нужны. TypeScript 5.9.3 включён в runtime dependencies для установок npm `--omit=dev`.

```sh
project-context explain redactSecrets --json
project-context affected redactSecrets --depth 2 --limit 50 --json
project-context path buildContextPack ensureFreshIndex --depth 8 --json
project-context explain 'src/context-pack/pack.ts#buildContextPack' --json
```

Те же read-only операции доступны в MCP как `explain({symbol, limit})`,
`affected({symbol, depth, limit})` и `path({from, to, depth})` во всех профилях.
Имена ищутся точно, с учётом регистра. При неоднозначности возвращаются кандидаты
с `id`, `file`, `line`, `endLine`; повторите запрос с ID или `file#name`.
Нельзя автоматически выбирать первый одноимённый символ.

`explain` показывает входящие и исходящие calls/imports. Для каждого ребра
возвращаются файл и строка вызова/импорта, для символа — место объявления.
`affected` обходит эти связи в обратном направлении, возвращая для каждой новой
сущности глубину и ребро `via`. Это потенциальное влияние, а не доказательство
изменения поведения. Импорт файла также не доказывает вызов каждой его функции.
`path` ищет кратчайший **направленный** путь по числу рёбер и возвращает его
символы и связи в порядке обхода. Путь до самого себя содержит один узел и ноль рёбер.

Состояния: `found`, `ambiguous`, `not_found`; для path также `no_path` и
`truncated`. `no_path` означает отсутствие пути в извлечённом графе, не во всей
программе. `truncated: true` в affected означает, что остаются непосещённые
связи за лимитом глубины/результатов. Explain ограничен 1–200 связями, affected —
глубиной 1–8 и 1–200 сущностями, path — глубиной 1–20 и 5000 посещённых узлов.
Неоднозначные ответы содержат не более 50 кандидатов.

Каждая операция сначала принудительно проверяет свежесть существующего индекса.
Связи пересоздаются транзакционно при изменении, переименовании или удалении
исходников. Смена схемы автоматически перестраивает старый одноразовый индекс.
Оригинальные Markdown-записи и исходники не изменяются.

## Охват и ограничения

Обрабатываются настроенные `source_globs` для `.ts/.tsx/.mts/.cts` и JS-аналогов.
Compiler API разрешает локальные относительные импорты, алиасы, повторные экспорты,
имена в лексических областях видимости и статически определимые методы. Граф
содержит именованные функции, методы, конструкторы, классы, типы и переменные
с простым именем (включая arrow/function инициализаторы). Вызовы из верхнего уровня привязаны к узлу файла.

В ответах есть `coverage`: количество поддержанных и неподдержанных файлов и
ограничения. Импорты связываются с доступными именованными/default функциями;
namespace-вызов может разрешаться, но отдельное ребро импорта namespace не создаётся.
Внешние пакеты, tsconfig paths, динамические импорты/вызовы и полноценный анализ
полиморфизма не поддержаны. Для остальных языков сохраняется существующий поиск
символов, но calls/imports не строятся. Отсутствие ребра не доказывает отсутствия
зависимости. Встроенный TypeScript не исполняет код и не загружает внешние модули.
